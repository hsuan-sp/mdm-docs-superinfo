**Apple’s official architecture provides three core methods for provisioning Managed Apple Accounts: Automated SFTP Upload (SIS integration), Manual CSV Web Import, and Federated Authentication.**

Given the massive influx of new students and departing graduates every semester, selecting the optimal provisioning strategy is crucial for minimizing the IT department's administrative burden.

## Comparison of Provisioning Strategies:

| Provisioning Method          | Ideal Scenarios                                                                                                                | Key Features & Technical Demands                                                                                                                                                                                                         |
| :--------------------------- | :----------------------------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Manual CSV Import**        | Small-scale schools without a Student Information System (SIS), or for processing a handful of mid-semester transfer students. | The lowest barrier to entry. Simply upload filled CSV templates via the ASM web interface. Lacks automated synchronization capabilities.                                                                                                 |
| **SFTP Upload**              | Schools with comprehensive SIS platforms requiring automated, recurring bulk roster updates every semester.                    | Supports both Apple’s proprietary CSV templates and the industry-standard OneRoster 1.1 format. Highly automated, suitable for processing thousands of records seamlessly.                                                               |
| **Federated Authentication** | Modern campuses fully standardized on Google Workspace or Microsoft Entra ID.                                                  | **The most forward-looking approach.** When a user signs in for the first time using their school email, ASM generates the Apple Account instantly in the background, achieving true Single Sign-On (SSO) and "Zero-Touch" provisioning. |

## 1. Uploading Data via SFTP (High Automation / SIS Integration)

If your school has engineering support or an SIS capable of automated exports:

- **Supported Standards**: You may use the standard Apple CSV format or OneRoster CSV.
- **The Technical Workflow**:
  1. **Establish Connection**: Enable SFTP in ASM settings to generate your unique SFTP URL, username, and secure password.
  2. **Package Data**: Export your rosters and compress all required CSV files into a single **ZIP archive**.
  3. **Secure Transmission**: Use an SFTP client (like FileZilla) to connect, and drag the ZIP file strictly into the root folder named `dropbox` (Note: This is Apple's internal server directory nomenclature and has absolutely no relation to the commercial "Dropbox" cloud service).
  4. **Backend Parsing**: ASM automatically decompresses the ZIP and overwrites the database. Administrators can download error logs from the ASM portal if formatting issues arise.
- **The Golden Rule of SFTP**: Following the initial payload, every subsequent upload must contain **ALL** complete CSV files (Classes, Courses, Locations, Rosters, Students, Staff). Even if you are only adding one new student, you cannot upload a delta file containing just that single row.

## 2. Federated Authentication (The Modern Hybrid Model)

This is the most highly recommended architecture for deployments utilizing **macOS 26** and modern iPads, perfectly marrying your Identity Provider (IdP) with educational rosters:

- **Separation of Identity**: Account creation, login verification, and password resets are entirely delegated to Google or Microsoft.
- **Roster Augmentation**: While the IdP handles identity, administrators can still utilize manual CSV uploads or SFTP to forge the links between "Classes" and "Rosters," enabling the Apple Classroom app to group students correctly.

## Strategy: Account Provisioning

1. **The 'Person ID' Integrity Disaster**: Whether using CSV or SFTP, the `person_id` column must be populated with a **permanently unique identifier** (we strongly recommend the **Official Student ID Number**). Never use temporary variables like "Grade+Class+Seat Number". If a student's `person_id` changes the following year, the system registers them as a brand-new user, entirely severing their access to previously saved iCloud data and causing catastrophic data loss.
2. **Implement Federation Early**: We strongly urge schools to abandon manual CSV uploads and fully transition to Federated Authentication. This guarantees that account lifecycle management remains fully automated and sustainable.
