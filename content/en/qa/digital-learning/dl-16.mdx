**Due to certain structural constraints within managed IT environments, school administrators require a highly precise operational workflow. The key to successful updates is verifying device connectivity and status before sending commands. Maintaining a proper software update SOP is critical for preserving the security posture and software compatibility of large-scale educational deployments.**

Most failures occur because devices are "unmanaged" or offline (e.g., Wi-Fi disconnected or in deep sleep). Sending update commands to unresponsive devices is futile.

## Standard Operating Procedure (SOP):

### 1. Wake Devices and Update Inventory

Before sending an OS update, push an **Update Inventory** command to the target group.

- **Goal**: Confirm the device is "alive" and retrieve the latest **Battery Level** and **Available Space** data.
- **Indicator**: If "Update Inventory" remains "Pending," the device is offline. Do not send the OS update yet; it must be physically unlocked and connected.

### 2. Filter Eligible Devices (Smart Group)

Use the fresh inventory data to filter for a "Ready to Update" group:

- **Battery > 50%**: This is an Apple hardware requirement; the command will fail otherwise.
- **Available Space > 10 GB**: To prevent storage-related failures during extraction.

### 3. Send the Remote Command

- Use **Mass Actions > Send Remote Commands**.
- Select **Update OS version on supervised devices**.
- **Key Settings**:
  - Target Version: `Latest version based on device eligibility` (or specific versions like iPadOS 26.5).
  - Action: **`Download and install the update, and restart devices after installation`**. (Selecting 'Download Only' will require manual user interaction to complete the update).

### 4. Batched Deployment

If the school lacks a **Content Caching** server, send updates in batches (e.g., one classroom at a time) to avoid overwhelming the school's external bandwidth.
