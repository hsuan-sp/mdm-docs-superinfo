**This is usually because the iPad has 'Private Wi-Fi Address' enabled, preventing the school firewall or DHCP server from identifying the device by its hardware MAC address.**

## Technical Background:

The Private Address feature was introduced in iPadOS 14. In **iPadOS 18** and the current **iPadOS 26**, this feature is categorized as:

- **Fixed**: Uses a consistent random address for a specific Wi-Fi network (Default).
- **Rotating**: Changes the address periodically. This high level of privacy often causes campus network systems—which frequently rely on MAC binding or IP reservations—to fail or block the connection.

## MDM Solution (Universal Disable):

Administrators should not ask students to adjust this manually. Instead, use Jamf Pro to push a unified Wi-Fi configuration profile:

1. In Jamf Pro, navigate to **Configuration Profiles > Wi-Fi**.
2. In the **Private Wi-Fi Address** (or "MAC Address Randomization") option, select **Disabled**.
3. **Result**: When the iPad connects to this SSID, it is forced to use its real hardware MAC address, allowing network infrastructure (like MAC authentication and security logs) to function correctly.

## Strategy:

- **Permanent Fix**: We recommend disabling MAC randomization for all school-deployed Wi-Fi profiles to minimize connection drops and technical support requests.
- **Limitation**: This MDM setting only applies to Wi-Fi networks deployed via configuration profiles. If a student manually joins a Wi-Fi network, they must still manually go to **Settings > Wi-Fi > (i) Icon** to disable the Private Address.
