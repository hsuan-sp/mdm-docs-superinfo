**Incomplete usage data is typically caused by the protection app (e.g., Jamf Trust) not running in the background, devices remaining offline for extended periods, or incomplete MDM configuration profiles.**

To maintain accurate network usage statistics and cybersecurity dashboards, the protection app must remain active in the system background. If a device shows zero activity or missing data, follow these standard troubleshooting steps:

## Common Causes & Solutions:

### 1. App being Force-Closed (Most Common)

- **The Issue**: Students often "swipe up" to close all apps in the multitasking view. This kills the Jamf Trust background process, stopping all data reporting.
- **The Fix**: Educate students that Jamf Trust is a "System Service" that must always be left open in the background. Note: You can also use MDM restrictions to prevent students from removing the app entirely.

### 2. Network Firewall Blocks

- **The Issue**: The device is on Wi-Fi, but the campus firewall is blocking the specific AWS or Jamf Cloud ports required for reporting.
- **Test**: Connect the device to a mobile hotspot. If the data uploads immediately, you need to ask the network administrator to allowlist Jamf’s reporting domains.

### 3. Profile Desynchronization

- **The Issue**: The Jamf Trust app is installed, but the underlying **DNS Proxy** or **Content Filter** profile is missing from the system configuration.
- **The Fix**: Send an **"Update Inventory"** command to the device via Jamf Pro. If the problem persists, attempt to re-push the network protection configuration profile.

## Strategy: Dashboard Reporting Delays

Usage dashboards often have a **T+1 delay** (24-hour lag). If you fix a device today for internal tracking, you likely won't see the updated status in your dashboard until the following day.
