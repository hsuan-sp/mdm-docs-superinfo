**"Declarative App Management" is a modernized MDM framework introduced in iOS/iPadOS and macOS. It empowers devices to "autonomously" manage their own app installation and update states, fundamentally replacing the traditional model that heavily relied on the MDM server frequently pushing remote commands.**

## Comparison: Traditional VPP vs. Declarative App Management

| Feature               | Traditional MDM (InstallApplication)                                                                   | Declarative App Management (App Declaration)                                                                                                       |
| :-------------------- | :----------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Trigger Mechanism** | The MDM server must "actively" push an installation command. If it fails, the server must retry.       | The MDM simply transmits a "Declaration." The device **autonomously** attempts installation until successful.                                      |
| **Status Reporting**  | Passive. The MDM must periodically wait for the device to "Check-in" to learn the installation status. | **Real-time**. The device proactively uses a dedicated channel to instantly report whether the installation is downloading, successful, or failed. |
| **Update Control**    | Limited to global "Automatic Updates" or entirely manual pushes.                                       | Can be configured per **individual app**: force updates, delay updates, or respect the user's App Store preferences.                               |
| **Deployment Scope**  | App Store Apps, VPP Apps.                                                                              | App Store Apps, VPP Apps, Custom Apps, and crucially, standard `.pkg` installers on macOS.                                                         |

## Supported Platforms and Requirements

- **iOS / iPadOS**: Fully supports declarative deployment for App Store and Custom Apps.
- **macOS**: Extends declarative deployment capabilities to include enterprise `.pkg` installers alongside standard apps.

## Setup in Jamf Pro

On DDM-compatible versions of Jamf Pro:

1. Navigate to **Blueprints > App Management**.

2. Create an **App Declaration**.
3. Set **Installation Behavior**:
   - **Required**: App is mandatory and unremovable. If a user tries to delete it, the device reinstall it automatically.
   - **Optional**: Appears in Self Service; user can remove it.

4. Set **Update Behavior**:
   - **Automatic**: Always keeps the app at the latest version.
   - **Follow User Preference**: Respects the toggle in the local App Store settings.

## Best Practice Deployment Recommendations

- **Transition for New Devices**: For devices meeting the minimum OS requirements, we strongly recommend fully transitioning to the Declarative App Management framework. This significantly reduces Jamf Pro server load while vastly improving deployment success rates on endpoints.
- **Hybrid Environment Strategy**: Legacy devices will still require the traditional VPP assignment model. Utilize Jamf Pro "Smart Groups" to categorize devices by OS version and apply the appropriate deployment strategy to each cohort.
- **Leverage Proactive Monitoring**: Take full advantage of DDM's real-time status reporting to rapidly identify devices where installations are stalled or failing, allowing IT admins to intervene promptly.
