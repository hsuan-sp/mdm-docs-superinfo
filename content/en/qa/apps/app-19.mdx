**Native "Single App Mode" cannot be exited by the user on the device once applied. If you require the flexibility to exit the app (e.g., after completing an exam), you should use "Autonomous Single App Mode (ASAM)".**

The underlying operational logic of these two modes is fundamentally different. Misconfiguration is a primary cause of devices becoming "stuck" when network connectivity fluctuates:

## Mode 1: MDM-Enforced Single App Mode

- **Characteristics**: The MDM administrator sends a remote command to lock the device into the app. Unless the administrator sends a subsequent "Unlock" command, the student **absolutely cannot exit the app**.
- **Risks**: **Network loss equals a stuck device**. If the device loses its Wi-Fi connection while locked, the user cannot return to the Home Screen to access Settings and reconnect. The device will never receive the MDM unlock command, requiring rescue via a **physical wired network adapter (RJ45)** or a forced restore.
- **Use Cases**: Library catalogs, digital signage, or kiosks (stationary devices that do not require user configuration and have stable networks).

## Mode 2: Autonomous Single App Mode (ASAM) — Recommended for Exams

- **Logic**: Permission is delegated to the app. When a student starts an exam, the **App locks itself**. Once the exam is submitted, the **App unlocks itself**.
- **Benefit**: No network dependency for unlocking. Even if the Wi-Fi drops, the student can finish the exam and the app can release the lock locally.
- **Setup**: In Jamf Pro, add the app's Bundle ID to the "Autonomous Single App Mode" allowlist in a Restrictions profile.

## Mode 3: Guided Access (Small Scale Only)

- **Characteristics**: This is a built-in iOS accessibility feature, not an MDM remote command. The proctor manually triple-clicks the power button to lock it, and triple-clicks again entering a passcode to unlock it.
- **Advantages**: Completely controlled by the on-site staff, eliminating the risk of network-related lockouts.

## Deployment Recommendations

- **Formal Exams**: Strongly advise software vendors to support **ASAM** (e.g., LockDown Browser), as it is the most secure and professional method. iOS 18+ integrates ASAM into the DDM declarative framework, allowing the device to maintain its locked state based on local declarations even during temporary network drops, greatly improving exam stability.
- **Pop Quizzes**: If the teaching app does not support ASAM, advise teachers to use **"Guided Access"** for manual, localized control.
- **To Avoid**: Avoid using MDM-Enforced Single App Mode for large-scale student exams unless you can guarantee absolute Wi-Fi stability in the testing environment and have the on-site capability to handle stuck devices.
