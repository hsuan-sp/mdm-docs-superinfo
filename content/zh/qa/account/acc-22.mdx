**Apple 官方架構提供了三種建立「管理式 Apple 帳號」的核心途徑：SFTP 自動化上傳 (SIS 整合)、手動 CSV 網頁匯入，以及聯合驗證 (Federated Authentication)。**

因應每學期大量新生入學與舊生畢業的流動，選擇正確的帳號建置策略能巨幅降低資訊組的行政負擔。

## 三種建置方式的優劣比較：

| 建置方式            | 適合對象與情境                                                        | 核心特點與技術要求                                                                                                               |
| :------------------ | :-------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------- |
| **手動 CSV 匯入**   | 小規模學校、無校務資訊系統 (SIS)，或需處理臨時的幾位轉學生。          | 直接將填妥的 CSV 檔案透過 ASM 網頁介面上傳。操作門檻最低，但不具備自動化同步能力。                                               |
| **SFTP 上傳**       | 具備完整校務資訊系統 (SIS) 且需要每學期定期自動化更新學籍資料的學校。 | 支援 Apple 官方範本與業界標準的 OneRoster 1.1 格式。自動化程度極高，適合數千人規模的大量資料處理。                               |
| **聯合驗證 (推薦)** | 已全面導入 Google Workspace 或 Microsoft Entra ID 的現代化校園。      | **最具前瞻性的作法。** 師生首次使用校方信箱登入時，ASM 會自動在後台即時建立 Apple 帳號，達成「單一登入 (SSO)」與「零接觸建檔」。 |

## 1. 透過 SFTP 上傳 (高度自動化/SIS 整合)

若學校有專屬的工程團隊或支援 SFTP 匯出的校務資訊系統 (SIS)：

- **支援標準**：可選用 Apple CSV 格式或 OneRoster CSV 1.1 規格。
- **操作流程**：
  1. **建立連線**：在 ASM 的設定中開啟 SFTP 連線，取得專屬的 SFTP URL、使用者帳號與密碼。
  2. **打包資料**：將所有名冊 CSV 檔案打包成一個 **ZIP 壓縮檔**。
  3. **加密傳輸**：使用 FileZilla 等 SFTP 軟體連線，將 ZIP 檔拖曳至伺服器的 `dropbox` 根目錄中（注意：此為 Apple SFTP 的預設內部目錄名稱，與商業雲端硬碟 Dropbox 毫無關聯）。
  4. **後台解析**：上傳完成後，ASM 會自動解壓縮並覆蓋更新資料庫。若有格式錯誤，管理員可至 ASM 下載報錯紀錄檔 (Log) 進行除錯。
- **技術鐵則**：建立連線後，未來的每一次更新都必須上傳「所有」六份完整的 CSV 檔案（包含 Classes、Courses、Locations、Rosters、Students、Staff）。即使只新增一名轉學生，也絕對不可只上傳該學生的單行資料。

## 2. 聯合驗證 (現代化混合模式)

這是在 **macOS 26** 與現代 iPad 部署中最被推崇的管理架構，完美結合了身分提供者 (IdP) 與教學名冊：

- **身分驗證分離**：帳號的建立、登入驗證與密碼管理全權交由 Google 或 Microsoft 負責。
- **課程資料補強**：在聯合驗證的基礎上，管理員仍可透過手動 CSV 上傳來建立「班級 (Classes)」與「課程名冊 (Rosters)」的關聯，以利 Apple Classroom 的編組運作。

## 實務建議：帳號建置策略

1. **Person ID 的唯一性災難**：不論您選擇 CSV 或 SFTP，`person_id` (人員 ID) 欄位必須是 **永久唯一的識別碼**（強烈建議填入**學號**或**身分證字號**）。絕對不可使用「入學年份+班級+座號」這類會隨升級而變動的數字。一旦 Person ID 改變，系統會視其為全新使用者，導致舊帳號的雲端資料被孤立，引發嚴重的資料遺失災難。
2. **盡早導入聯合驗證**：強烈建議各校徹底捨棄傳統的 CSV 手動匯入，全面轉向 Google 或 Microsoft 聯合驗證。這將確保學校的帳號生命週期管理能達成真正的全自動化。
