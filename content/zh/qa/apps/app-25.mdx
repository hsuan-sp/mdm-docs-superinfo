**自 macOS (Tahoe) 世代起，Apple 正式將非 App Store 來源的企業級安裝軟體 (.pkg) 納入宣告式裝置管理 (DDM) 框架。這提供了比傳統 Jamf Policy 更現代化、低延遲且高度透明的軟體部署體驗。**

## DDM Package vs. Jamf Policy

| 特性         | Jamf Policy (傳統架構)                                     | DDM Package Declaration (宣告式新架構)                                |
| :----------- | :--------------------------------------------------------- | :-------------------------------------------------------------------- |
| **運作核心** | 高度依賴 `Jamf` binary 代理程式在背景執行腳本與安裝        | 依賴 macOS 作業系統原生的 MDM 框架直接執行安裝                        |
| **觸發時機** | 必須設定觸發條件 (Trigger)，如 Login 或 Recurring Check-in | **自主評估 (Autonomous)**。只要裝置判定符合宣告條件，系統即刻嘗試安裝 |
| **狀態回報** | 回報至 Jamf Pro logs，且有輪詢時間差                       | **即時回報**。安裝進度、錯誤代碼皆立即推播至 MDM 狀態通道             |
| **離線支援** | 執行 Policy 的當下必須連線至 Jamf Pro 伺服器               | 只要裝置已收到 Declaration，後續可在背景離線自行處理                  |
| **適用軟體** | 任何自訂安裝檔或腳本 (.pkg, .dmg, .sh)                     | 限於經過 Apple 標準簽署之 **Distribution Package (.pkg)**             |

## 適用條件與限制

- **macOS 版本需求** ：macOS 26 (Tahoe) 或更新版本。
- **.pkg 檔案要求** ：
  - 必須由 **Apple Developer ID Installer certificate** 正確簽署。
  - 必須為標準的 Distribution Package 格式。
  - 安裝路徑需符合 macOS 安全性要求（通常為 `/Applications` 資料夾）。

## 何時該用哪一個？

### 何時應優先使用 DDM Package？

- 部署標準架構的大型軟體（如 Microsoft Office, Google Chrome, Adobe Acrobat）。
- 需要在 Jamf Pro 中即時監控「安裝成功率」的關鍵必備軟體。
- 針對新採購的 Mac 設備，希望建立不高度依賴 Jamf binary 的現代化管理環境。

### 何時應繼續維持使用 Jamf Policy？

- 部署流程極度複雜的軟體（例如：安裝完成後必須執行 Bash Script 修改特定 `.plist` 設定檔，或跳出互動視窗）。
- 非標準 `.pkg` 格式的封裝檔（如拖曳式的 `.dmg` 應用程式）。
- 尚未更新至最新 macOS 版本的舊款設備。
- 高度依賴前置 (Pre-flight) 或後置 (Post-flight) 腳本的部署情境。

## Jamf Pro 設定步驟 ：

1.  確保 .pkg 已由 Apple Developer ID 正確簽署。
2.  在 Jamf Pro 建立 **Package Declaration** （位於 Blueprints 或 Packages 區域）。
3.  上傳 .pkg 檔案至 Jamf 分發點。
4.  設定部署條件（可選）：例如僅在磁碟空間 > 10GB 時安裝。
5.  指派給目標裝置或裝置群組。

## 專家建議 ：

- **混合使用策略** ：對於 macOS 26 以上裝置優先使用 DDM，舊版裝置保留 Policy，透過 Smart Groups 自動區分。
- **公證 (Notarization) 是關鍵** ：macOS 26 的 DDM 部署對安全性要求極高。 **所有 .pkg 檔案必須經過 Apple 公證 (Notarized)** ，否則裝置將拒絕安裝，並在 Status Channel 回報 `VerificationFailed` 錯誤。
- **測試先行** ：新軟體部署前，建議先在測試裝置上驗證 .pkg 是否具備完整的簽署鍊與公證票據。
